## 二、Mathis 吞吐量公式：丢包如何摧毁你的网速？

计算机网络领域著名的 **Mathis 吞吐量数学模型** 揭示了 TCP 在跨国网络中的性能天花板：

$$\text{最大吞吐量 (Throughput)} \le \frac{\text{MSS}}{\text{RTT} \times \sqrt{p}}$$

其中：
- $\text{MSS}$ 为最大报文段长度（通常约 1460 字节）；
- $\text{RTT}$ 为往返时延（例如中美专线 130ms）；
- $p$ 为**网络丢包率（Packet Loss Rate）**。

```
丢包率对跨国网络单线程吞吐量的毁灭性打击（实测数据）：
┌────────────────────────────────────────────────────────┐
│ 丢包率 = 0.00% (优质 IEPL 专线)： 跑满 500Mbps - 1000Mbps│
├────────────────────────────────────────────────────────┤
│ 丢包率 = 0.50% (轻微拥塞)：       骤降至 85Mbps        │
├────────────────────────────────────────────────────────┤
│ 丢包率 = 1.50% (中度拥塞)：       骤降至 22Mbps (看4K吃力)│
├────────────────────────────────────────────────────────┤
│ 丢包率 = 3.00%+ (公网中转晚高峰)： 跌破 8Mbps (连1080P都卡)│
└────────────────────────────────────────────────────────┘
```
**结论极其残酷**：只要机场线路在晚高峰存在哪怕 2% 的丢包，你的千兆家庭宽带在单线程访问时就会缩水成“几兆小水管”。

### 1. 本地 Wi-Fi 干扰深度自查
2.4GHz Wi-Fi 的物理信道极其拥挤，隔壁邻居的路由器、蓝牙耳机、甚至微波炉都会引发严重的本地丢包。
- **实操**：进入路由器后台，将 2.4GHz 与 5GHz 频段分离，电脑手机务必**只连接 5GHz Wi-Fi**；有条件的情况下，台式机尽量直插六类（CAT6）千兆网线。

### 2. 拥塞控制算法：为什么 BBR 如此重要？
传统的 TCP Cubic 算法一旦遇到丢包，会激进地将发包速度砍掉一半；而 Google 开发的 **BBR（Bottleneck Bandwidth and RTT）** 算法，能够通过实时测量带宽与 RTT，在存在丢包的高拥塞跨国公网中依然保持高速发送。
- 确保你选购的机场其海外落地机房**全节点开启了 BBRv3** 加速内核。

### 3. 更换更耐丢包的现代协议
如果必须在公网劣质网络下工作，可在客户端中选用基于 UDP 开发的新一代抗丢包协议：
- **Hysteria 2 / TUIC**：基于 QUIC（UDP）开发，内置了激进的丢包自适应补偿算法，即使在 10%–20% 的恶劣弱网丢包环境下，依然能暴力跑满视频带宽。

<summary><strong>Q1：为什么白天看 4K 非常丝滑，每天一到晚上八九点就卡成 PPT？</strong></summary>
<p>
这表明你的机场使用的是<strong>普通的公网中转或公网直连线路</strong>。每天晚上 20:00–23:00 是全国网民集中上网的晚高峰时期，中国电信 163、中国联通 169 的国际出口总带宽会被彻底挤爆，导致公网跨境丢包率从白天的 0.5% 瞬间飙升至 25% 以上。只有采购了不经过公网国际出口、独占物理海底光缆带宽的纯正 <strong>IEPL / IPLC 专线机场</strong>（如 <a href="/reviews/guangsu">光速云</a>），才能做到全天 24 小时没有任何高峰期减速。
</p>
</details>

<details>
<summary><strong>Q2：开启客户端的多路复用（MUX）能提升看视频的速度吗？</strong></summary>
<p>
<strong>看视频不会提升，甚至可能变卡！</strong> 多路复用（MUX）的核心价值是将多个并发小连接（如网页加载 50 张小图片、API 短连接）合并进单条 TCP 通道中传输，从而节省频繁 TCP 三次握手的时间。但在高码率视频持续大文件拉流时，单通道 MUX 反而容易引发队头阻塞（Head-of-Line Blocking）。因此看大视频时建议关闭 MUX。
</p>
</details>
