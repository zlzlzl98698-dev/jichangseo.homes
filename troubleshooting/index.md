## 三、故障一：节点连接全部超时（Timeout / 绿色虚假延迟 / 无法连通）

* **典型表象**：在客户端中点击延迟测试，所有节点全部显示红色 `Timeout`，或者显示诱人的绿色延迟（如 20ms）但实际打开网页却无限转圈。
* **核心诱因剖析**：
  1. **本地系统时间偏差**：现代 TLS 1.3 通信要求客户端与服务端时间戳严格一致。偏差大于 90 秒时，握手直接被服务端拒绝；
  2. **国内入口前置机被防火墙阻断**：敏感时期机场的前置入口域名或 IP 遭受流量封锁；
  3. **客户端显示虚假延迟（Fake Ping）**：仅测试了国内前置机的连通性，而中转机到海外落地机之间的专线已经物理中断。
* **标准修复对策**：
  * **第一步**：打开 Windows【时间与语言】->【日期和时间】，确认开启“自动设置时间”，点击【立即同步】；
  * **第二步**：登录机场官网后台，手动复制最新的订阅链接，在客户端中点击【更新订阅】，同步最新可用入口节点；
  * **第三步**：在客户端配置中，将延迟测试 URL 修改为端到端目标地址：`https://cp.cloudflare.com/generate_204`。

## 四、故障二：关掉客户端后电脑彻底断网（系统代理残留终极修复）

* **典型表象**：退出代理软件后，电脑上的微信、腾讯会议能正常使用，但 Chrome、Edge、火狐浏览器打开任何网页均报错：“无法连接到代理服务器”或 `ERR_PROXY_CONNECTION_FAILED`。
* **根本机理解构**：客户端在退出时，未能成功在 Windows 注册表中将 `ProxyEnable` 键值重置为 0。操作系统的网络协议栈依然将所有 HTTP 请求强行发送至 `127.0.0.1:7890`，而此时该本地端口由于软件关闭已经处于无监听状态。
* **标准修复对策（耗时 10 秒）**：
  1. 打开 Windows【设置】-> 点击【网络和 Internet】-> 点击左侧或右侧的【代理】；
  2. 找到【手动设置代理】下方的**“使用代理服务器”**开关；
  3. 手动将其切换为**【关闭】**状态，并清空下方的 IP 与端口输入框，点击【保存】即可瞬间恢复正常上网。

## 五、故障三：订阅链接拉取失败（HTTP 403 / 500 / 证书报错）

* **典型表象**：在客户端输入订阅链接点击拉取后，弹出对话框报错：`Download error: 403 Forbidden`、`500 Internal Server Error` 或 `x509: certificate signed by unknown authority`。
* **核心诱因与对应处置方案**：
  * **情况 A（403 Forbidden）**：套餐流量耗尽或套餐已过期。请登录机场后台检查账单配额；
  * **情况 B（网络连接被阻断）**：当前本地 WiFi（如学校、大型企业内网）将机场订阅服务器的域名列入了内网 DNS 黑名单。**立即将电脑连接手机移动 4G/5G 热点**，再次点击拉取通常可秒级成功；
  * **情况 C（SSL 证书报错）**：本地电脑缺少根证书或开启了第三方抓包工具。关闭系统内所有代理拦截工具，或者在客户端中临时开启“跳过证书验证（Skip Cert Verify）”。

## 六、故障四：订阅拉取成功但节点列表完全为空

* **典型表象**：客户端提示订阅导入成功，但展开节点列表时，内部没有任何节点名称，或者只显示一个不可点击的空白组。
* **核心诱因剖析**：
  1. 订阅格式不兼容（例如：将旧版 Clash 专用的 YAML 订阅导入了仅支持新版 sing-box 的软件中）；
  2. 机场后台生成订阅时发生了空指针异常，返回了一段空文本。
* **标准修复对策**：
  * 在浏览器地址栏中直接粘贴该订阅链接并按下回车，观察下载下来的文本文件内容；
  * 若内容为空，联系机场客服重新下发配置；
  * 若内容为经过 Base64 编码的长文本，可在机场后台寻找“Clash 格式转换”导出专用订阅，或使用通用工具导入。

## 七、故障五：客户端启动闪退与本地端口冲突（127.0.0.1:7890 占用）

* **典型表象**：双击启动客户端后没有任何窗口弹出，或者启动后立即报错退出，日志中高频出现：`bind: address already in use` 或 `listen tcp 127.0.0.1:7890: bind: An attempt was made to access a socket in a way forbidden by its access permissions`。
* **根本机理解构**：另一个网络程序已经在后台占用了 `7890` 端口。这通常是因为上一次客户端被非正常杀死后，底层内核进程（如 `clash-meta.exe`）依然在后台驻留运行。
* **彻底根治实操**：
  1. 按下快捷键 `Ctrl + Shift + Esc` 打开任务管理器；
  2. 在【详细信息】面板中，按名称排序寻找：`clash-verge.exe`、`mihomo-windows-amd64.exe`、`xray.exe` 或 `v2rayN.exe`；
  3. 右键点击全部进程，选择【结束进程树】；
  4. 重新启动客户端软件，端口绑定冲突即可彻底消除。

---

## 八、故障六：QQ微信正常聊天，但所有网页无法打开（DNS 污染与瘫痪）

* **典型表象**：即时通讯工具（微信、QQ、钉钉）文字收发自如，游戏客户端联机顺畅，但所有网页浏览器（包括国内百度与国外谷歌）全部无法加载，提示 `DNS_PROBE_FINISHED_BAD_CONFIG`。
* **标准排查与修复三步法**：
  ```bash
  # 第一步：以管理员身份打开 CMD 命令提示符，强制刷新本地系统 DNS 缓存
  ipconfig /flushdns

  # 第二步：释放并重新获取本地 DHCP 租约
  ipconfig /release
  ipconfig /renew
  ```
  * **第三步：固定本地网卡主 DNS**：进入【网络连接】属性 -> 双击【Internet 协议版本 4 (TCP/IPv4)】-> 手动指定 DNS 服务器为：首选 `223.5.5.5`（阿里公共 DNS），备选 `119.29.29.29`（腾讯公共 DNS）。

## 九、故障七：TUN 模式无法启动与 Wintun 驱动损坏修复

* **典型表象**：在客户端中点击【TUN 模式】开关后，开关自动弹回关闭状态，或者提示 `create tun interface failed: wintun driver error`。
* **深度修复对策**：
  1. **赋予最高管理员特权**：完全退出客户端，右键点击图标选择【以管理员身份运行】；
  2. **手动清理损坏的虚拟网卡**：
     * 按下 `Win + X` 打开【设备管理器】；
     * 展开【网络适配器】，寻找名为 `Wintun Userspace Tunnel` 或带有黄色感叹号的虚拟适配器；
     * 右键点击选择【卸载设备】，勾选“尝试为此设备删除驱动程序”；
     * 重新在客户端中开启 TUN 模式，程序会自动写入最新的干净驱动模块。

## 十、故障八：AI 工具阻断（ChatGPT / Claude Error 1020 根除）

* **典型表象**：正常网页浏览毫无障碍，但打开 ChatGPT 页面时弹出灰黑色安全警告：`Error 1020: Access Denied`，或者 Cloudflare 人机验证框无限循环打钩刷新。
* **根除实操三步法**：
  1. **紧急切换专属低风险专线**：在客户端策略组中选择香港以外的节点，优先选用标注了【原生/AI】后缀的美国或新加坡专线；
  2. **清除本地被标记的追踪 Token**：在 Chrome 地址栏打开：`chrome://settings/content/all?searchSubpage=openai`，点击【删除所有显示的 Cookie 和网站数据】；
  3. **禁用浏览器冲突插件**：暂时停用可能会篡改 HTTP 请求头的第三方翻译插件与去广告扩展。

## 十一、故障九：流媒体播放受限（Netflix 仅自制剧与画质严重降权）

* **典型表象**：Netflix 登录正常，但搜不到任何当地独家热播剧（如《绝命毒师》），只能看到自制剧；或者播放 4K 视频时强制降速至 480P 模糊画质。
* **根本机理解构**：节点 IP 已被 Netflix 商业版权库标记为“机房托管 IP（Hosting IP）”，触发了非自制剧版权保护隔离。
* **解决对策**：
  * 在客户端中切换至机场明确标注“原生解锁（NF）”后缀的专属节点；
  * 在播放界面按下快捷键 `Ctrl + Alt + Shift + S` 调出码率控制菜单，检查是否有 4K 视频流供手动锁定。

## 十二、故障十：国内应用异常卡顿与异地登录风控报警

* **典型表象**：连接代理后，国内 APP（如美团、京东、淘宝）经常要求短信验证码二次认证，甚至提示异地登录安全警告；看国内 B站视频频繁卡顿。
* **彻底根治方案**：
  * 核心元凶是**误开启了【Global（全局模式）】**；
  * **必须在客户端主界面将模式切换为【Rule（规则模式）】**；
  * 在规则列表中确认国内各大主流网站均匹配 `DIRECT` 规则走本地直连路由出站。

## 十三、如何准确区分“本地网络故障”与“机场服务端宕机”

当网络彻底中断时，不要第一时间向机场客服投诉，请按照以下对照表精准隔离责任方：

| 测试诊断动作 | 若测试结果为【通过】 | 若测试结果为【失败】 | 判定归属方 |
| :--- | :--- | :--- | :--- |
| **手机断开 WiFi，用 4G 流量打开机场官网** | 机场服务端网站正常在线 | 机场官网彻底无法访问，提示超时 | 官网打不开 ➔ **机场服务端发生重大故障** |
| **终端执行 \`ping 223.5.5.5\` 测试本地网关** | 本地物理宽带完全正常 | 提示“请求超时”或“常规错误” | 本地断网 ➔ **用户本地家庭宽带欠费/故障** |
| **手机流量开启热点让电脑连接测试** | 电脑连接热点后翻墙顺畅恢复 | 电脑连热点依然无法翻墙 | 连热点正常 ➔ **用户本地路由器/运营商局域网拦截** |
| **切换其他不同国家地区（如日本换美国）** | 换地区后立即恢复正常 | 全站所有国家节点无一可用 | 单地区故障 ➔ **特定跨国海缆光纤突发故障** |

## 十四、核心日志（Logs）阅读技巧与高频关键错误代码速查表

在客户端左侧菜单中找到【日志（Logs）】，日志是诊断疑难杂症的最终法宝：

| 日志核心关键词片段 | 核心网络诱因剖析 | 现场处置方案 |
| :--- | :--- | :--- |
| `dial tcp: i/o timeout` | 连接远端服务器超时，通常由于前置机被阻断 | 更换其他地区节点，更新订阅获取最新节点 |
| `context deadline exceeded` | 请求在设定的超时阈值内未完成响应 | 本地丢包严重或运营商骨干网发生拥堵 |
| `certificate signed by unknown authority` | 本地 SSL 证书链异常，疑似受到中间人嗅探 | 关闭抓包软件，或在设置中开启“跳过证书检查” |
| `dns resolve failed` | 域名解析彻底失败，DNS 上游服务器失联 | 修改本地网卡主 DNS 为 223.5.5.5，刷新缓存 |
| `handshake failed: remote closed connection` | 远端服务器主动强行挂断了加密握手会话 | 节点服务端核心程序崩溃或正在热重启 |

## 十五、向机场提交高价值工单的专业范式与规范

向服务商提交工单时，**清晰精准的信息能让工程师在 5 分钟内为您解决问题**：

* **❌ 极度低效的错误提单示范**：“为什么连不上？”、“坏了快修！”、“怎么老是断线？”（技术客服无法从这种工单中获取任何有效调试信息）。
* **✅ 专业高效的提单范式模板**：
  > **工单标题**：【故障申报】上海电信网络下，香港IEPL-02节点出现连接超时  
  > **使用设备与系统**：Windows 11 专业版 64位  
  > **客户端版本**：Clash Verge Rev v1.6.0（Mihomo内核）  
  > **本地宽带运营商**：上海电信千兆家宽  
  > **故障发生时间**：2026年11月21日 21:30 晚高峰  
  > **故障现象简述**：本地 `ping 223.5.5.5` 正常（延时 5ms，0丢包）。切换日本和美国节点能正常打开网页，唯独香港 01–04 专线节点点击连通性测试全部显示红字 Timeout。  
  > **附带日志关键报错**：`dial tcp 118.xx.xx.xx:443: i/o timeout`  
  > **已自检步骤**：已尝试同步系统时钟，已尝试刷新本地 DNS，确认非本地断网。
