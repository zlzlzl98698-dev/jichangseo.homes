## 一、内链拓扑总体设计：网状金字塔架构

为彻底杜绝死链、孤岛页面（Orphan Pages）并使 PageRank 权重在站内最高效流动，网站构建了四层立体的网状金字塔拓扑：

```
                    ┌────────────────────────────┐
                    │     网站首页 (Domain Root) │
                    └─────────────┬──────────────┘
                                  │ (全局主导航 10 大分类)
                                  ▼
         ┌────────────────────────────────────────────────────────┐
         │              10 个一级主专题 (Pillar Hubs)              │
         │   (/airport/, /pricing/, /brands/, /clients/, etc.)    │
         └─────────────┬────────────────────────────┬─────────────┘
                       │ (专题索引与二级卡片)        ▲ (面包屑与向上回流)
                       ▼                            │
         ┌────────────────────────────────────────────────────────┐
         │             68 个权威二级专题 (Sub-Topic Hubs)          │
         │   (/airport/rankings, /tutorials/tun-mode, etc.)       │
         └─────────────┬────────────────────────────┬─────────────┘
                       │ (锚文本深度交叉互联)        ▲ (向上锚定所属专题)
                       ▼                            │
         ┌─────────────────────────┐    ┌─────────────────────────┐
         │ 32 家品牌万字独立深度评测│<──>│  未来的三级深度长尾文章集群│
         │   (/reviews/guangsu)    │    │  (/tutorials/clash-...) │
         └─────────────────────────┘    └─────────────────────────┘
```

## 二、二级专题四大内链交互规范

全站 68 个二级专题页面严格执行以下四大内链工程规范：

### 1. 向上回流机制（Breadcrumb & Context Flow）
- 每个二级专题在开头或关键决策段落，均自然嵌入其所属一级主专题的权威链接（如 `/tutorials/tun-mode.md` 内链回流到 `[使用教程主索引](/tutorials/)`）；
- 确保爬虫在抓取任意叶子节点时，能够顺畅回溯到分类核心。

### 2. 横向同级穿透（Horizontal Sibling Mesh）
- 逻辑强相关的二级专题之间必须建立网状互联，打破“树状孤立”：
  - `network/iepl`（IEPL专线）直接横向锚定 `network/iplc`（IPLC专线）与 `network/bgp`（BGP中转）；
  - `troubleshooting/timeout`（全部超时）直接横向锚定 `troubleshooting/subscription-fail`（订阅失败）与 `tutorials/dns-leak`（DNS排查）；
  - `clients/clash-verge-rev` 直接横向锚定 `tutorials/tun-mode`（TUN模式配置）与 `tutorials/clash-rules`（规则分流）。

### 3. 向下商业漏斗转化（Commercial Conversion Flow）
- 每一个技术探讨型、场景型、排障型二级专题，在涉及方案推荐、硬件专线对比与选型时，均**精准锚定至对应的 32 家品牌独立深度评测页面**：
  - 提到“顶级 IEPL 专线 / 综合体验第一” ──> 锚定 `[光速云深度评测](/reviews/guangsu)`；
  - 提到“极限游戏低延迟 / 纯物理 IPLC” ──> 锚定 `[微风网络独立评测](/reviews/weifeng)`；
  - 提到“永久不限时备用 / 压箱底防失联” ──> 锚定 `[星岛梦独立评测](/reviews/xingdaomeng)`；
  - 提到“小白免配置专属客户端” ──> 锚定 `[飞猫云独立评测](/reviews/feimao)`；
  - 提到“商务外贸大并发与多工位” ──> 锚定 `[暮光加速独立评测](/reviews/muguang)`。

### 4. 严格 URL 规范（Clean URL 无尾斜杠）
- 按照 VitePress 与 Apache 静态部署规范，全站所有引向具体 markdown 页面的内链，**一律采用无尾部斜杠的纯净路径**（例如 `/reviews/guangsu`，严格禁止写成 `/reviews/guangsu/`）；
- 目录索引主页面统一采用标准目录路径（例如 `/airport/`、`/pricing/`）。

## 四、内链锚文本（Anchor Text）自然度审计

为了防止触发搜索引擎的“关键词过度堆砌（Keyword Stuffing）”惩罚，内链锚文本进行了严格的多样化设计：
- **品牌词变体**：使用“光速云”、“光速云深度评测”、“GuangSu Cloud”交替出现；
- **技术属性变体**：使用“企业级 IEPL 物理专线”、“晚高峰 0 丢包专线”、“纯物理 IPLC 线路”自然融入段落上下文中；
- **场景属性变体**：使用“极速 AI 研发节点”、“全节点解锁 ChatGPT 的服务商”、“电竞级游戏加速专线”引导点击。
