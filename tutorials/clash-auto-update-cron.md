# Clash Verge配置自动定时更新订阅与健康巡检：告别手动点击全自动实战

::: tip 💡 核心结论与速查清单
- **自动更新必要性**：机场为应对网络波动与运营商封锁，会定期更换中转机房入口 IP。若数周不更新订阅，本地保留的旧节点会逐步失效。
- **最佳更新频率**：建议设置为 **`1440` 分钟（即 24 小时自动更新一次）**；切忌设置低于 60 分钟，过于频繁的拉取会被机场 WAF 判定为恶意攻击而触发 403 临时封锁！
- **健康检查（Health Check）黄金搭配**：开启节点的定时健康检查，设置间隔为 300 秒，确保客户端在毫秒级识别故障节点并自动绕行。
:::

## 一、Clash Verge Rev 自动定时更新三步实操

以目前最主流的现代化开源客户端 **Clash Verge Rev** 为例，分步配置流程如下：

```
                    ┌────────────────────────────┐
                    │    订阅自动更新配置时序    │
                    └─────────────┬──────────────┘
                                  │
         【1. 进入左侧导航栏的「订阅 (Profiles)」页面】
                                  │
                                  ▼
         【2. 鼠标右键你的订阅卡片，选择「编辑信息 (Edit Info)」】
                                  │
                                  ▼
         【3. 在「更新间隔」一栏填入数字：1440 (单位为分钟)】
                                  │
                                  ▼
         【4. 点击保存，系统即可每 24 小时在后台静默自动拉取最新配置】
```

## 二、配置内核自动健康检查（Health Check）

自动更新解决了“节点 IP 是否最新”的问题，而**健康检查**解决了“当前节点死没死”的问题。

在策略组（如 `🚀 节点选择` 或 `♻️ 自动优选`）中，确保包含以下探针参数：

```yaml
proxy-groups:
  - name: ♻️ 自动优选
    type: url-test
    url: http://www.gstatic.com/generate_204  # 国际公认零缓存测试探针
    interval: 300                            # 每 300 秒 (5分钟) 全量测速一次
    tolerance: 50                            # 延迟容差设置为 50ms (防止频繁跳跃)
    proxies:
      - 🇭🇰 香港专线01
      - 🇭🇰 香港专线02
      - 🇯🇵 日本专线01
```

### 容差参数（Tolerance）的实战价值：
- 如果没有设置 `tolerance: 50`，当节点 A 延迟为 30ms、节点 B 延迟为 28ms 时，系统会因为 2ms 的微小波动频繁切换路线，导致网页登录态（Cookie/Session）反复失效被踢下线；
- 加上 50ms 容差后，只有当新节点比旧节点快 50ms 以上时才会触发切换，兼顾了低延迟与极端稳定性。
