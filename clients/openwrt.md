## 一、软路由两大主流硬件拓扑架构深度对决：主路由 vs 旁路由

在家庭或小型外贸工作室部署 OpenWrt 时，拓扑选型直接决定了整个家庭网络的稳定上限：

```
+-----------------------------------------------------------------------------------------+
| 拓扑 1: 单网口旁路由模式 (By-pass Gateway - 强烈推荐)                                   |
+-----------------------------------------------------------------------------------------+
| [光猫] ──(光纤)──► [硬路由器 (主路由 192.168.1.1 负责拨号与全家 Wi-Fi)]                 |
|                            │                                                            |
|                            ├──────────────┬──────────────────────────────┐              |
|                            ▼              ▼                              ▼              |
|                  [普通智能家电/长辈手机]  [软路由 (旁路由 192.168.1.2)]  [普通有线设备] |
|                  (网关: 192.168.1.1)      (运行 OpenClash 专线)          (直连不折腾)   |
|                  (直接走国内物理宽带)             │                                     |
|                                                   ▼                                     |
|                                         [需要出海的设备 (Apple TV / PS5 / 办公电脑)]    |
|                                         (手动将【默认网关】修改为: 192.168.1.2)         |
|                                         (全天候无感享受专线秒开，软路由挂掉全家不断网)  |
+-----------------------------------------------------------------------------------------+
```

* **为什么不推荐普通家庭直接将软路由当“主路由拨号”**：软路由通常运行在第三方开源固件上，一旦系统因升级内核或配置失误发生死机崩溃，全家人的手机、电视盒子、智能吸尘器瞬间全部瘫痪，极度影响家人生活质量。**旁路由模式是兼具极客自由度与全家高可用的黄金分割点**。

## 三、旁路网关（旁路由）标准网络参数与全屋透明加速流水线

按照以下网络参数规范进行配置，可彻底规避绝大多数新手配置导致的断网：

```
+-----------------------------------------------------------------------------------------+
| 旁路由标准网络参数配置表                                                                |
+-----------------------------------------------------------------------------------------+
| [主路由器参数 (假设)]                                                                   |
|  * 局域网 IP 地址 (LAN IP)：192.168.1.1                                                 |
|  * DHCP 服务器：开启（自动给全家普通设备分配 IP，默认网关分配 192.168.1.1）            |
|                                                                                         |
| [旁路由 (OpenWrt) 网络参数设置 (进入 网络 -> 接口 -> LAN)]                              |
|  * 传输协议：静态地址 (Static)                                                          |
|  * IPv4 地址：192.168.1.2（必须与主路由在同一网段，且不与局域网其他设备 IP 冲突）      |
|  * 子网掩码：255.255.255.0                                                              |
|  * IPv4 网关：192.168.1.1（必须严格指向主路由器 IP）                                   |
|  * 自定义 DNS 服务器：192.168.1.1 或 119.29.29.29                                      |
|  * 【核心关键】：在最底部的【DHCP 服务器】设置中，**勾选【忽略此接口 (关闭 DHCP)】**！  |
+-----------------------------------------------------------------------------------------+
```

## 四、软路由最致命两大顽疾根治：DNS 死循环与网关互锁

在软路由实战部署中，90% 的网络瘫痪问题来自以下两个致命配置冲突：

### 顽疾 1：DNS 死循环（DNS Loop / 回环风暴）
* **故障现象**：软路由运行几分钟后，局域网 CPU 占用率 100%，所有网页打不开；
* **根因剖析**：主路由把 DNS 指向旁路由，而旁路由的国内上游 DNS 又错误指向了主路由，导致一个简单的域名解析在两个路由器之间无限循环反弹，瞬间挤爆网络；
* **彻底根治方案**：
  * **旁路由的【系统自定义上游 DNS】坚决直接填写公网公共 DNS**（例如腾讯 `119.29.29.29` 或阿里 `223.5.5.5`），绝不要再指回主路由 IP！

### 顽疾 2：单臂路由丢包与防火墙数据包伪装
* **故障现象**：设备把网关指向旁路由后，可以 Ping 通内网，但无法打开任何外部网页；
* **彻底根治方案**：
  * 进入 OpenWrt【网络】→【防火墙】→【自定义规则】，在最底部追加一行 iptables 伪装命令并重启防火墙：
    ```bash
    iptables -t nat -I POSTROUTING -o eth0 -j MASQUERADE
    ```
    *（注：命令中的 `eth0` 需替换为你旁路由实际的 LAN 口网卡接口名称）*。

## 六、OpenWrt 软路由常见核心疑问深度解答（FAQ）

<details>
<summary><strong>Q1：使用旁路由后，全家所有设备的网速会被软路由的性能拖慢吗？</strong></summary>
<p>完全不会。在标准的“旁路由架构”下，只有那些你手动将【默认网关】指向软路由的设备（如你的工作笔记本、Apple TV），数据包才会经过软路由处理；全家父母的手机、平板、智能电视的网关依然指向主路由，直接走电信原厂千兆宽带直连，软路由哪怕遭遇断电拔线，也绝对不会影响普通家人的上网体验。</p>
</details>

<details>
<summary><strong>Q2：为什么在软路由上首选 Fake-IP 模式？</strong></summary>
<p>在传统的“真实 IP 模式（Redir-Host）”下，设备发起访问前必须先等待本地向海外公共 DNS 递归解析出真实 IP，这会导致首次打开海外网页有明显的 1-2 秒白屏卡顿。而 <strong>Fake-IP 模式</strong> 会在本地极速返回一个虚拟的保留 IP（如 198.18.x.x），真正的域名解析被推迟到海外专线节点端并发完成，从而实现全屋设备<strong>“秒开网页、零首包延迟”</strong>的极致丝滑体验。</p>
</details>

<details>
<summary><strong>Q3：软路由需要购买非常昂贵的工控机硬件吗？</strong></summary>
<p>不需要。如果只是满足家庭 5-10 台设备同时看 4K 视频，百元级的 ARM 架构盒子（如斐讯 N1）或搭载 Intel J4125 / N100 的低功耗小主机足以为千兆网络提供满血转发。软路由真正的值钱核心在于**底层搭配的专线服务商（如光速云）**，一条 0 丢包的优质物理专线远比堆砌昂贵的 CPU 硬件重要得多。</p>
</details>

<details>
<summary><strong>Q4：正规机场支持直接给 OpenClash 提供订阅吗？</strong></summary>
<p>主流正规大厂（如**[光速云](/reviews/guangsu)**、**[微风网络](/reviews/weifeng)**等）均提供标准的 Clash 完整配置订阅。在 OpenClash 插件管理后台，直接点击【配置文件订阅】→ 粘贴机场订阅链接 → 点击【保存并应用】，几秒钟内即可全自动拉取所有专线节点，省心省力。</p>
</details>
